# DriveAssistant 주행 분석 설계

## 이번에 적용한 감속 관찰

`CarRestrictionsMonitor`에서 받은 `PERF_VEHICLE_SPEED`의 차량 타임스탬프와 m/s 값을 `MainActivity`가 `DecelerationSession`에 직접 전달한다. Compose의 속도 상태는 화면 표시용으로 사용한다. 일반 Android 데모는 두 속도 시나리오를 같은 분석기에 재생한다. [Pleos 차량 속도 FAQ](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/vehicle-app-faq)

| 단계 | 동작 |
| --- | --- |
| 속도 입력 | 연수 시작 전 샘플과 중복·역순 타임스탬프는 건너뛴다. 후진과 전후진 경계는 감속 계산에서 제외한다. 신호가 2초를 넘겨 끊기거나 Activity가 중단되면 평가를 보류한다. |
| 감속 추정 | 0.1초 이상 떨어진 유효 속도 쌍에서 `d = (이전 속도 − 현재 속도) / Δt`를 계산한다. 최대 감속은 이 구간 평균의 최댓값이다. |
| 사건 감지 | `d > 3.0 m/s²`인 구간이 연속 0.6초 이상이면 후보 1회를 기록한다. `d ≤ 2.0 m/s²`가 연속 0.3초 이상이어야 새 후보를 받을 수 있다. |
| 결과 공개 | 전진 속도 구간 4개 이상과 `d > 0.2 m/s²` 감속 시간 3초 이상을 확보하면 후보 수와 구간 최대 감속을 표시한다. 실차 화면은 `CarUxRestrictions`가 허용된 상태를 반환한 뒤 조작과 결과를 제공한다. |

표의 수치는 파일럿 데이터로 조정할 초기값이다. 속도 샘플 사이의 값은 구간 평균으로만 해석한다. 부드러운 데모는 `0회 / 1.5 m/s²`, 급한 데모는 `1회 / 4.0 m/s²`가 설계상 기대값이다. 기존 실험용 점수는 데모에서만 표시한다. 속도 기반 감속 후보에는 브레이크 페달 조작, 회생 제동, 방어 제동이 모두 포함될 수 있다. 결과에는 감속 당시 교통 상황을 복기할 수 있는 한 문장을 붙인다.

## 주행 습관 분석으로 확장

| 단계 | 적용 방식 | 판정 조건 |
| --- | --- | --- |
| 차량 신호와 맥락 | 차량과 권한이 지원하는 경우 Brake 등 읽기 신호를 속도와 시간으로 맞춘다. 도로 유형이나 개입 신호가 들어오면 해당 사건에 맥락을 붙인다. | 개입이 확인된 사건은 별도 관찰로 분리한다. 정보가 없거나 불확실한 사건은 원인 미확인으로 남긴다. |
| 부드러움의 강도 | 실제 수신 간격이 충분히 짧고 일정한 경우 이동창 속도 회귀로 가속도를 추정한다. 이후 `j = Δa / Δt`를 구해 감속 크기, 지속 시간, jerk를 같은 속도대에서 비교한다. | 파일럿에서는 유효 수신 간격의 90%가 0.2초 이내이고, 각 1초 창에 유효 샘플이 5개 이상인 구간부터 검토한다. 원본 타임스탬프와 센서 지원 범위로 이 기준을 보정한다. |
| 상황별 개선 추세 | 예를 들어 같은 저속 정지 연수에서 `b`는 개선이 필요하다고 분류된 정지 수, `n`은 맥락과 데이터가 확인된 전체 정지 수다. 기준군 비율 `p₀`와 보정 강도 `k`를 두고 `(b + k × p₀) / (n + k)`로 표본이 적을 때 비율이 튀는 문제를 줄인다. | 같은 연수 단계, 속도대, 도로 유형에서 모은 기록을 비교한다. 초기 집계 기준은 이틀 이상에 걸친 3회 연수, 유효 정지 20회다. 비교 구간이 강사 기준과 겹치면 `추가 관찰`을 표시한다. |
| 연수 단계 피드백 | 주차 중 선택한 운전자 프로필과 연수 단계별로 요약을 보관한다. PR #5의 `StepEvaluator`가 합쳐지면 결과 모델에 관찰 근거와 다음 연습을 전달한다. | 실제 연수 평가는 강사 판정이 확보된 항목부터 적용한다. 감속만 수집된 세션에는 감속 항목을 표시한다. |

자연 주행 연구에서 가속도와 속도, jerk는 행동 패턴의 특징으로 쓰인다. 한 번의 주행과 제한된 신호로 면허 경력이나 전체 운전 숙련도를 추정하기에는 상황과 개인차의 영향이 크다. 앱은 표본이 적으면 `데이터 부족`, 충분하면 항목별 관찰 결과와 지난 연습 대비 변화를 보여주는 방향으로 설계한다. [운전 스타일과 숙련도 연구](https://pubmed.ncbi.nlm.nih.gov/36931183/) · [종방향 jerk 연구](https://pubmed.ncbi.nlm.nih.gov/28499141/)

## 다음 작업

1. 대상 Pleos 차량·지역·앱 카테고리의 주행 중 데이터 접근과 Activity 동작을 확인한다. 주차 확인 신호와 Brake의 지원 여부 및 권한을 확인한 뒤, 플랫폼이 허용한 경로로 연수 종료와 결과 공개를 연결한다. [주행 안전 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline) · [지역별 주행 규제](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy) · [Vehicle SDK](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/intro)
2. 허용된 환경에서 평상시 정지·저속 정체·상황이 기록된 방어 제동 데이터를 모은다. 강사가 관찰한 감속 이유를 구분하고, 운전자와 경로가 겹치지 않게 데이터를 나눠 오탐률과 누락률을 비교해 초기값을 보정한다.
3. 보정된 기준으로 같은 연수의 최근 기록을 비교해 연습 한 가지를 추천한다. 항목이 추가될 때는 사용 가능한 신호와 실제 평가한 기회 수를 결과에 함께 제공한다.

현재 차량 세션은 Activity가 살아 있는 동안 수집한다. 주행 제한으로 Activity가 중단되면 그 세션은 평가 보류로 표시된다. 주행 중 지속 수집 가능 여부는 대상 Pleos 환경과 앱 정책에 따라 확인이 필요하다.
