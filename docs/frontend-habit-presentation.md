# 운전 습관 분석 표시 규칙

습관 분석 후속 계획의 2단계 기록입니다. 기존 `DrivingHabitAnalysis`를 읽어 화면에서 사용할 근거 상태와 평가 상태를 분리했습니다. 이 단계의 원본 변경은 순수 Kotlin 매핑과 JVM 테스트이며, 이후의 [습관 분석 화면 단계](frontend-habit-analysis.md)에서 목록·상세 화면·탐색에 연결합니다. 아래 매핑 규칙은 그대로 유지합니다.

## 변경 대상과 경계

- `ui/model/HabitAnalysisPresentation.kt`: 항목 종류, 원본 상태와 관찰 횟수를 보존하는 표시 모델 및 변환 함수.
- `ui/model/HabitAnalysisPresentationTest.kt`: 누락·0회·미충족·평가 보류와 기존 Mock의 회귀 검증.
- 이 문서: 표시 규칙, 가정, 완료 기준과 팀원 리뷰 항목.

선행 조건은 [점수 대시보드](frontend-score-dashboard.md)의 기존 UI 모델과 Mock 기반입니다. 평가 모델, 저장소·ViewModel 인터페이스, Mock fixture, 차량 제한 정책은 수정하지 않습니다. 서버 계약, 종합 점수, 숙련도·티어 기준을 정의하지 않습니다.

## 근거 상태

`evidence`는 전달받은 횟수의 사실만 나타냅니다. `HAS_MET`는 일부 또는 전부 충족한 관찰이 있다는 뜻이며, 항목 전체의 합격 판정이 아닙니다.

| 원본 관찰 횟수 | 근거 상태 | 표시용 횟수 |
| --- | --- | --- |
| `null` | `NOT_PROVIDED` — 근거 미제공 | 없음 |
| `0 / 0` | `NO_OBSERVATIONS` — 관찰 0회 | 없음 |
| `0 / n`, n > 0 | `NONE_MET` — 관찰했으나 충족 0회 | 원본 `0 / n` |
| `m / n`, m > 0 | `HAS_MET` — 충족 관찰 있음 | 원본 `m / n` |

`observations`에는 원본 값을 그대로 남깁니다. 향후 화면은 `countsForDisplay`로 횟수 표시 여부를 결정하므로 관찰 0회를 `0 / 0` 비율로 표시하지 않습니다. 횟수를 백분율이나 점수로 환산하지 않습니다.

## 평가 상태와 가정

아래는 UI 표시를 위한 임시 정책이며 평가기를 다시 구현하거나 서버의 유효성 규칙을 확정하지 않습니다. 원본 상태는 `reportedStatus`에 보존합니다.

| 조건 | 화면 평가 상태 |
| --- | --- |
| 관찰 횟수 미제공 또는 관찰 0회 | 원본 상태와 관계없이 `DEFERRED` — 평가 보류 |
| 원본 `UNOBSERVED` | 횟수가 있어도 `DEFERRED` |
| 관찰이 있고 원본 `REVIEW` | `REVIEW` — 횟수가 모두 충족이어도 원본 평가 유지 |
| 충족 관찰이 있고 원본 `MET` | `MET` — 전부 충족이어야 한다는 기준을 추가하지 않음 |
| 원본 `MET`이지만 충족 횟수 0회 | 성공 표시의 근거가 없으므로 `DEFERRED`; 원본 상태·횟수 보존 |

평가 보류 중에도 양수인 관찰 횟수는 표시 가능합니다. 예를 들어 `UNOBSERVED`와 `3 / 3`을 받으면 근거는 `HAS_MET`, 평가는 `DEFERRED`입니다. 횟수만으로 평가를 추론하지 않습니다. 정차·신호 시작·유지·소등은 각각 독립적으로 매핑하며 합산하지 않습니다.

## 완료 기준과 검증

- 근거 미제공, 관찰 0회, 관찰 후 충족 0회가 서로 다른 상태로 보존됨.
- 평가가 보류되는 경우와 원본 평가가 유지되는 경우가 위 표와 일치함.
- 원본 모델·Mock을 변경하지 않고 정상·부분 누락 fixture를 매핑함.
- 신규 JVM 테스트와 기존 테스트가 통과하며 앱·테스트 APK 컴파일 및 Lint에서 오류가 없음.

검증 결과: `:app:assembleDebug`, `:app:testDebugUnitTest`, `:app:lintDebug`, `:app:assembleDebugAndroidTest`가 모두 통과했습니다. JVM 테스트는 기존 44개와 신규 12개를 합쳐 56개이며 실패·오류·건너뜀은 0개입니다. Lint 오류는 0개이며 기존 파일의 리소스·복수형·의존성 안내 등 경고 19개가 남아 있습니다. 새 표시 모델과 테스트 파일에는 Lint 경고가 없습니다.

이번 단계에는 화면 변경이 없으므로 Preview 실제 렌더링이나 기기 UI 테스트 실행은 포함하지 않습니다. 테스트 APK는 컴파일만 확인했습니다.

## 팀원 리뷰 요청

- 근거 상태와 평가 상태가 독립적이라는 구분이 상세 화면 구현에 충분한지 확인해 주세요.
- 근거가 없는 `MET`과 충족 0회의 `MET`을 성공으로 표시하지 않는 임시 정책을 확인해 주세요.
- `REVIEW`의 전부 충족 횟수나 `UNOBSERVED`의 양수 횟수를 UI가 재평가하지 않는지 확인해 주세요.

상세 화면, 문구 리소스, 접근성 설명, Preview와 화면 전환의 구현·검증은 [별도 화면 검토 문서](frontend-habit-analysis.md)에서 확인합니다.
