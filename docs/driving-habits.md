# 숙련된 운전 습관을 연습 과제로 만드는 방법

## 관찰 행동과 초보자의 연습 목표

| 숙련된 행동 | 초보자의 목표 | 평가할 수 있는 근거 |
| --- | --- | --- |
| 움직이기 전에 주변을 확인한다 | 미러로 흐름을 보고 이동 직전에 사각지대를 다시 확인한다. | 이번 앱에서는 안내 문구로 연습한다. 실제로 보았는지는 강사의 관찰이나 운전자가 정차 후 남긴 체크에 근거한다. |
| 미리 의도를 알려 준다 | 바꿀 방향의 방향지시등을 충분히 앞에서 켠다. | 방향지시등 상태와 독립적으로 확인한 차로 변경 시작 위치가 필요하다. |
| 안전한 간격이 생길 때까지 기다린다 | 신호를 켠 뒤에도 옆 차로의 공간이 부족하면 이동을 미룬다. | 모의 연수에서 접근 중인 차량을 먼저 보내는 선택을 별도로 평가한다. 실차 평가는 옆 차로 차량의 위치, 접근 속도와 차로 변경 시점을 믿을 수 있을 때만 한다. |
| 동작을 안정적으로 마무리한다 | 차로 변경이 끝날 때까지 신호를 유지하고, 새 차로에 자리 잡으면 끈다. | 방향지시등과 변경 완료 위치로 평가한다. 차로 중앙 유지까지 평가하려면 차로 안의 위치와 도로 곡률 근거를 추가한다. |

도로주행시험에서 방향지시등을 미리 켜는 시점, 변경 중 유지, 완료 후 중지를 각각 보는 점을 모의 연수에 반영했다. 주변 확인, 신호, 기동을 묶는 교육 자료도 참고했다. ## 구현한 방향지시등 연수

일반 Android와 지원되는 Pleos 디버그 빌드의 모의 연수 홈에서 **방향지시등 연수**를 열고 교통 상황과 왼쪽 또는 오른쪽 차로 변경을 고른다. 사용자는 8개 모의 장면에서 방향지시등을 켜거나 끈 뒤 다음 장면으로 넘긴다. 차로 변경 시작·완료 위치는 시나리오가 제공한다. 결과 화면은 세 신호 행동을 따로 보여 준다. 다음 연습은 안전 간격 판단에서 보완할 점을 먼저 고르고, 그다음 신호 행동을 본다. 차로 변경 전에는 뒤차 접근, 시야 가림 또는 간격 확인 장면에서 ‘기다리기’와 ‘지금 이동하기’ 중 하나를 고른다. 이 선택은 신호 결과와 별도로 피드백한다. 이동 장면은 안전한 간격이 확인된 뒤 시작한다.

| 평가 | 일반도로 모의 연수 규칙 |
| --- | --- |
| 미리 켜기 | 시작 시점에 맞는 신호가 켜져 있어야 한다. 가장 최근에 해당 방향을 켠 위치부터 변경 시작 위치까지 30m 이상이어야 한다. 중간에 껐다 켜면 마지막으로 켠 위치를 쓴다. |
| 변경 중 유지 | 시작부터 완료 직전까지 같은 방향을 유지해야 한다. 완료 위치에서 끄는 조작은 허용한다. |
| 완료 후 끄기 | 새 차로에 자리 잡은 뒤 10m에 이르기 전에 신호를 끈다. 같은 모의 기동의 관찰이 끝나기 전에 다시 켰으면 복기로 표시한다. |

설계 예시로 변경까지 35m 남은 장면에서 맞는 신호를 켜고, 완료 장면에서 끄면 세 항목이 충족된다. 변경까지 25m 남은 장면에서 켜면 이후 행동이 같아도 미리 켜기 항목은 복기가 된다. 이 앱의 프리셋은 일반도로의 단일 모의 차로 변경을 대상으로 한다. 공도 적용 시에는 도로 종류와 적용 규칙을 확인하고, 다음 기동이 이어지는 경우 관찰 구간을 따로 나눈다.

`LaneChangeSignalEvaluator`는 모의 UI와 분리돼 있다. 신호 상태는 타임스탬프와 누적 거리가 있는 연속 관찰 기록을 받는다. 기동 시작·완료는 별도 출처가 제공한다. 누락과 비상등을 표시한 기록, 시작·완료를 덮지 못한 기록, 시간 또는 거리가 역전된 기록은 평가를 보류한다. 방향지시등 점멸의 개별 밝기 변화는 연속 신호 상태로 정규화한 뒤 평가해야 한다.

## Pleos 실차 연결 조건

1. 대상 차종과 앱 권한을 확인한다. Pleos SDK의 `checkTurnSignalStateCapabilities`, `getCurrentTurnSignalState`, `registerTurnSignalState`로 지원·초깃값·상태 변화를 확인한다. 조회에는 승인된 `pleos.car.permission.CAR_LIGHTS`가 필요하다. AAOS의 표준 스위치 상태가 제공되는 환경에서는 API 수준, 권한, 차량 지원을 확인해 선택한다. [TurnSignal SDK](https://document.pleos.ai/api-reference/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/turn-signal/entry) · [Pleos 권한](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle-permission) · [AAOS 프로퍼티](https://developer.android.com/reference/android/car/VehiclePropertyIds#TURN_SIGNAL_SWITCH)
2. 신호와 같은 기준 시계로 정렬할 수 있는 독립 기동 기록을 연결한다. 먼저 연수 영상 또는 강사 표식으로 차로 변경 시작과 새 차로 정착 위치를 표시한다. 승인된 차로 위치 신호를 사용할 수 있다면, 실제 차로 전환과 일치하는지 확인한 뒤 자동 검출에 사용한다. 핸들 각도 변화는 곡선과 회피에서도 나타나므로 그것만으로 차로 변경을 확정할 수 없다.
3. 신호를 켠 뒤 이동한 거리는 유효 속도 쌍의 평균 속도와 경과 시간으로 누적한다. 결손, 후진, 이벤트 지연 또는 거리 오차 때문에 임계값의 어느 쪽인지 확정할 수 없으면 해당 결과를 관찰 부족으로 둔다. 실제 방향지시등 조작과 차로 변경 기록을 정차 뒤 비교해 정확도를 보정한다.
4. 지원되는 범위 안에서만 수집한다. Pleos 디버그 빌드에서는 P와 조작 허용이 확인된 상태에서 모의 연수를 제공한다. 차량 결과 화면은 주차 상태와 `CarUxRestrictions`가 허용되는 범위에서 연다. [Pleos 주행 안전 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline) · [지역별 주행 규제](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy)

## 후속 평가

- **간격 판단**은 차로 변경 구간에서 옆 차로 앞뒤 차량을 식별하고 그 상대속도를 확보한 뒤 확장한다. 뒤 차량이 접근 중이면 `현재 뒤 간격 ÷ 접근 속도`를 함께 기록한다. 센서가 다른 차로의 차량을 잡았거나 위치가 불확실하면 결과를 보류한다. 기준값은 상황별 강사 판정으로 보정한다.
- **차로 정착**은 독립적으로 표시한 변경 완료 뒤의 차로 중심 편차를 차로 폭과 함께 기록한다. 비슷한 속도와 곡률의 구간끼리 비교하고, 회피 기동이나 차선 위치가 불확실한 구간을 분리한다.
- **주변 확인**은 모의 연수 안내와 강사 관찰표부터 적용한다. 영상이나 별도 승인 신호를 확보하기 전에는 깜빡이와 차량 속도로 미러나 사각지대를 실제로 확인했는지 판정할 수 없다.
