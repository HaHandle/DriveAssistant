# 4단계: Mock 점수 대시보드

점수 요약과 추이를 먼저 읽을 수 있도록 기존 코칭 화면에 기간 선택·그래프를 추가했습니다. 서버 인터페이스, 실제 점수 산정, 숙련도·티어 기준은 변경하지 않습니다. 분석 상세와 티어 전용 화면은 다음 단계입니다.

## 화면과 재사용 범위

- 최신 점수와 직전 기록 대비 변화는 기존 모델의 값을 그대로 표시합니다.
- 7일·30일·전체 선택은 기존 LiquidSelection을 재사용합니다. 선택값은 화면 저장 상태로 복원하며 SharedPreferences 키는 추가하지 않습니다.
- 좁은 창은 점수 → 추이 → 코칭 순서, 넓은 창은 점수·추이와 코칭·습관을 두 열로 배치합니다.
- 그래프는 Compose Canvas로 그립니다. 새 라이브러리나 저장소 조회 인자를 추가하지 않습니다.
- 로딩·빈 기록·오류에는 그래프를 남기지 않습니다. Ready 상태에서 추이만 없으면 별도의 기록 없음 안내를 표시합니다.
- 차량의 예시 데이터 차단과 UX 제한 화면은 기존 PresentationPolicy를 그대로 따릅니다.

## 표시 규칙과 가정

다음은 UI 표시를 위한 선택이며 서버 계약이나 평가 정책이 아닙니다.

| 항목 | 규칙 |
| --- | --- |
| 기간 기준 | 전달받은 추이의 마지막 기록일. 오늘 시각을 사용하지 않아 고정 Mock이 날짜에 따라 사라지지 않음 |
| 7일·30일 | 화면 시간대의 달력 날짜를 양끝 포함. 각각 마지막 날짜에서 6일·29일 전 자정부터 표시 |
| 전체 | 가장 오래된 기록일부터 마지막 기록일까지 표시 |
| 시간대 | 앱은 기기 시간대, 전용 Preview는 Asia/Seoul. 단위 테스트는 시간대를 명시 |
| 정렬 | 시각 오름차순. 입력 목록을 수정하지 않으며 같은 시각의 기록은 입력 순서를 유지 |
| 가로축 | 실제 경과 시간 비율. 기록 수에 맞춰 등간격으로 재배치하지 않음 |
| 세로축 | 기존 표시 범위인 0~100 고정. 실제 측정된 0점과 미측정을 구분 |
| 기간 비교 | 해당 기간의 첫 기록과 마지막 기록의 차이. 두 기록이 측정됐고 시각이 달라야 비교 |
| 미측정 | 0점으로 대체하거나 인접한 측정값으로 보간하지 않음. 해당 기록에서 선을 끊고 미측정 횟수 표시 |
| 동일 시각 | 두 점을 연결해 시간에 따른 변화를 만들지 않음 |
| 기록 0·1개 | 그래프 없음 안내 또는 측정점만 표시. 비교값을 만들지 않음. 시간 범위가 0이면 점을 중앙에 배치 |

기존 상단의 `이전 기록 대비`와 새 그래프의 `기간 첫 기록 대비`는 비교 대상이 다릅니다. 기간을 바꿔도 상단 최신 점수를 다른 값으로 재해석하지 않습니다. 평균 점수·실제 평가·등급을 새로 계산하지 않습니다.

정상 Mock은 40일 범위의 기록 9개를 사용합니다. 7일·30일·전체에서 각각 측정 4·8·9회와 변화 +6·+17·+20점을 표시합니다. 상단 최신 점수 92점과 직전 기록 대비 +4점은 유지됩니다. 부분 누락 Mock에는 기간 안의 중간·마지막 미측정을 포함합니다.

## 모션·가독성·접근성

기간 선택은 기존 180/240ms 리퀴드 선택 모션을 사용하고, 기간이 바뀔 때만 그래프가 진입 180ms·퇴장 90ms 페이드로 전환됩니다. 같은 기간의 데이터 갱신은 페이드를 시작하지 않고 즉시 새 결과로 교체합니다. 측정값을 변형하는 그래프 모핑이나 반복 애니메이션은 없습니다. 모션 끄기·백그라운드·차량 UX 제한으로 전환되면 진행 중인 페이드를 제거하고 목표 상태 하나만 바로 표시합니다.

본문과 축은 기존 18sp 이상 글자 체계를 사용합니다. 기간 선택은 최소 80dp 조작 영역을 유지하고, 좁은 영역·글자 배율 1.3 초과에서는 세로 선택으로 바꿉니다. 그래프 색상은 기존 주·야간 토큰을 사용합니다. Canvas에는 날짜·측정값·미측정을 읽는 접근성 설명을 제공합니다.

주요 그래프 선의 계산상 대비는 주간 7.70:1·야간 10.17:1, 축 글자는 주간 6.78:1·야간 8.53:1입니다. 실제 디스플레이 측정이나 공식 검수를 대신하지 않습니다.

## Preview와 검증

`ui/preview/ScoreDashboardPreview.kt`의 Score dashboard 그룹을 엽니다. 7일·30일·전체, 부분 누락, 추이 없음, 전부 미측정, 0점 한 개, 0~100점 경계의 8개 사례를 직접 주입합니다. 주간·야간·320dp/글자 200%·영문 구성을 제공합니다. 기존 App states Preview는 로딩·빈 기록·오류와 전체 화면 배치도 확인할 수 있습니다.

완료 기준:

- 기간별 기록·비교값이 갱신되고 저장 상태 복원 후 선택이 유지됨.
- 미측정·0점·기록 부족을 구분하고 누락된 지점으로 선을 연결하지 않음.
- 날짜 경계·시간대·일광절약시간·중복 시각·비교 대상의 단위 테스트 통과.
- 기존 기능과 함께 디버그 빌드·JVM 테스트·Lint·UI 테스트 APK 컴파일 통과.

최종 코드에서 JVM 56개(이번 단계 15개 추가, 실패·오류 0개), 디버그 빌드, Lint, UI 테스트 APK 컴파일이 모두 통과했습니다. 이번 대시보드 단계에는 기간 변경·미측정·0점·추이 없음·저장 상태 복원과 데이터 갱신·모션 해제 동작을 확인하는 Compose UI 테스트 7개가 포함됩니다. 이 중 `ScoreTrendPanelTest` 6개는 Pleos Connect v2.1.0 Android 14 에뮬레이터에서 실패·오류·건너뜀 없이 실행했습니다. Preview 정적 상태는 별도 증빙 PR에서 렌더링했습니다.

Preview 실제 렌더링, TalkBack 읽기, 물리적인 글자 크기·터치 영역과 차량 제한 전환은 대상 환경에서 추가 확인이 필요합니다. 에뮬레이터 부팅 문제는 조사하지 않습니다.

## 팀원 리뷰 요청

- 상단 직전 기록 비교와 그래프 기간 첫 기록 비교의 문구가 구분되는지 확인해 주세요.
- 마지막 기록 기준의 날짜 범위가 이해되는지, 미측정이 0점처럼 보이지 않는지 확인해 주세요.
- 큰 글자·좁은 창에서 기간 선택과 축·안내를 읽고 스크롤할 수 있는지 확인해 주세요.
- 로딩·오류·차량 제한에서 이전 그래프가 남지 않는지 확인해 주세요.
