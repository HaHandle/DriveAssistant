# 저장소 작업 안내

개발 현황과 통합 순서는 [이슈 #13](https://github.com/HaHandle/DriveAssistant/issues/13)에서 관리합니다. 완료 상태는 코드가 있는 브랜치, main 병합 여부, 검증한 커밋을 함께 확인합니다.

## 현재 작업 흐름

2026-11-10 기준 기능 PR은 검토 중이며 main에는 초기 Android 프로젝트가 있습니다.

| 흐름 | PR 순서 | 검토할 경계 |
| --- | --- | --- |
| 새 Compose 프론트엔드 | #11 → #12 → #15 | 기본 UI·모델·Mock → 상태 수집·재시도 → 점수 대시보드·기간별 추이. 분석 상세·티어 전용 화면은 후속 작업 |
| 공통 도메인 | #5 | 별도 작업. 기존 변경 요청 리뷰를 해결한 뒤 재검토 |
| 기존 연수 기능 | #4 → #8 → #9 → #10 | Mock 연수 → 감속·정차 → 방향지시등·간격 → 통합 연수 |

새 UI와 기존 연수 기능은 MainActivity·테마·차량 제한 처리에서 구현이 겹칩니다. 두 흐름의 PR을 모두 병합하는 것만으로 기능 연결이 완료되지는 않습니다. 기능을 새 UI에 연결하는 작업과 검증이 필요합니다.

서버 계약, 실제 종합 점수·숙련도·티어 기준은 미정입니다. UI 모델이나 Mock 값을 서버 DTO 또는 실제 평가 규칙으로 확정하지 않습니다.

## 브랜치와 PR

- main은 검토·검증된 변경의 통합 기준입니다.
- 새 작업은 갱신한 원격 기준에서 별도 feat/, fix/, test/, docs/, chore/ 브랜치로 시작합니다.
- 선행 작업 위에서 시작했다면 PR의 base를 해당 브랜치로 지정하고 선행·후속 PR을 본문에 연결합니다.
- 선행 PR 병합 후에는 후속 PR의 base·차이를 다시 확인합니다. squash 병합은 선행 커밋이 후속 PR에 다시 나타날 수 있으므로 특히 확인합니다.
- 검증이나 통합 조건이 충족되지 않은 변경은 초안 상태로 관리합니다. 기존 변경 요청 리뷰와 담당자를 정리 과정에서 제거하지 않습니다.
- 브랜치는 변경 보존 여부, 열린 PR의 head/base 사용 여부, 미완료 이슈를 확인한 뒤 정리합니다. 삭제 후보의 SHA는 #13에 기록합니다.
- 각 환경의 로컬 main에만 있는 커밋을 원격 main과 같다고 간주하지 않습니다. 원격과 차이를 확인하고 작업을 보존합니다.

## 기본 검증

기본 Android CI는 모든 대상 브랜치의 PR, main 푸시, 수동 실행을 받도록 구성합니다. 같은 PR의 이전 실행은 새 실행이 시작되면 취소합니다.

```text
./gradlew --no-daemon :app:assembleDebug :app:testDebugUnitTest :app:lintDebug :app:assembleDebugAndroidTest
```

JDK 25, Android SDK 37.0과 build-tools 36.0.0을 사용합니다. 보고서는 실행 결과의 android-validation 아티팩트에서 확인합니다. UI 테스트 APK 컴파일은 기기 UI 테스트 실행을 의미하지 않습니다. 기본 검증은 에뮬레이터를 부팅하지 않습니다.

이 설정을 추가하는 관리 PR이 main에 병합되기 전과 각 기능 브랜치에 반영되기 전에는 기존 CI가 적용될 수 있습니다. 설정 파일을 바꾸는 PR의 성공이 다른 PR의 자동 재실행이나 검증 완료를 의미하지 않습니다.

## UI·차량 검토

UI 변경은 Preview에서 주·야간, 넓은 창·분할 창, 영문, 글자 크기 200%, 로딩·빈 기록·오류·부분 누락을 확인합니다. 컴파일만 수행했다면 실제 렌더링은 미확인으로 남깁니다.

차량 검증은 대상 커밋·기기·권한·신호 값과 단위·수신 실패·UX 제한 전환을 기록합니다. 예전 커밋의 화면이나 로그를 최신 UI 검증으로 표시하지 않습니다. 에뮬레이터 부팅 문제 조사는 보류하며 기존 증빙과 남은 검증 항목은 유지합니다.
